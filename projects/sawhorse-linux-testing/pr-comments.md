## On issue #27 (macOS "Sawhorse.app is damaged"), if you want to help there

Not reproduced (no Mac here), so this is a pointer, not a confirmed cause. The report says the app was downloaded and unzipped, which suggests `Sawhorse_aarch64.app.tar.gz` rather than the `.dmg`. On macOS, an unsigned app extracted from an archive keeps the quarantine attribute, and Gatekeeper then reports it as "damaged" instead of offering the "Open Anyway" path the release notes describe for the `.dmg`. Two things to try: install from `Sawhorse_0.1.0-alpha.4_aarch64.dmg` and follow the release notes' steps; or, for the extracted app, clear the attribute once with `xattr -cr /Applications/Sawhorse.app` and open it again. If the `.dmg` shows the same message, that would point at something else, and worth saying so here.

## Reply on PR #33 (to caseycapshaw's review of 2026-11-06)

Thanks for trying it on a real file, and for the two suggestions. Both are in the branch now:

- The reader's notes (`Opened::notes`) go to stderr, one `sawhorse-cli: note: ...` line each, before the JSON on stdout, so stdout stays parseable and a script can tell a clean read from a repaired one. A clean file prints nothing there.
- `nest` takes `--algorithm guillotine|maxrects` (`table-saw` and `cnc` work as aliases); unset, it is the document's own as before, and `cutlist` refuses the option.

Tests cover both: each algorithm reaches the kernel and the JSON says which; a saved file rewritten with a `plugin-data.json` that is not text comes back with the reader's note and the same cut list. Clippy, fmt and the wasm32 check still pass.
